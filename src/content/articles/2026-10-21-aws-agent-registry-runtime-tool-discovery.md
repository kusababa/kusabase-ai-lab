*出典: [AWS Machine Learning Blog](https://aws.amazon.com/blogs/machine-learning/discover-tools-at-runtime-with-aws-agent-registry/)*

## ニュース概要

AWS Machine Learning Blogは、AWS Agent Registryを使って実行時にツールを発見する仕組みを紹介する記事を公開した。従来、AIエージェントのツール連携はビルド時にハードコードされることが多く、ツール数が数個から数百個に増えると管理が破綻しやすかった。本記事では、Discover（発見）、Instantiate（生成）、Execute（実行）の3ステップからなるランタイムループを提案し、オーケストレーターがMCPサーバーやA2Aエージェントをセマンティック検索によって動的に見つけ出す方法を解説している。

## 何が変わったか

最大の変化は「ビルド時にすべてのツールをコンパイルする」方式から「実行時に必要なツールだけを検索・生成する」方式への転換である。AWS Agent Registryはツールのメタデータをインデックス化し、自然言語や意味的な類似度に基づいてエージェントが適切なMCPサーバーやA2Aエージェントを選び出せるようにする。これにより、ツールカタログが数十、数百と拡大しても、エージェント側のコードを都度書き換える必要がなくなる。

## 開発者への影響

開発者にとっては、エージェントのスケーラビリティが大きく向上する一方で、新たな設計課題も生まれる。ツールの説明文やメタデータをセマンティック検索に最適化する必要があり、従来のAPI仕様書作成とは異なるスキルが求められる。また、実行時に動的に選ばれたツールが期待通りに動作するかの検証（スキーマバリデーションやサンドボックス実行）が重要になる。さらに、AWSエコシステムへの依存度が高まるため、マルチクラウド戦略を取る組織はMCP/A2Aの標準準拠度を注視する必要がある。

## KusaBase視点の考察

この動きは、かつてマイクロサービスの世界で起きた「サービスディスカバリ」の進化と酷似している。ConsulやEurekaがハードコードされたエンドポイント管理からの脱却を実現したように、AIエージェントの世界でも『ツールディスカバリ』が次の標準インフラになりつつある。ただしKusaBase編集部として注目したいのは、実行時に未知のツールを動的に組み込む仕組みは利便性と引き換えにセキュリティリスクを内包する点だ。誰が登録したツールなのか、悪意あるMCPサーバーが紛れ込んだ場合の信頼検証はどう行うのか——この設計思想がAWSのクローズドなエコシステム内でどこまで担保されるかは不透明だ。医療AIのような高信頼性が求められる領域では、こうした動的発見の仕組みをそのまま適用するにはガバナンス層の追加実装が不可欠になるだろう。単なる利便性向上としてではなく、エージェント基盤における『信頼の発見』という新たな課題提起として捉えるべきニュースである。

## 今後の予測

今後、AWS以外のクラウドベンダーやOSSコミュニティも同様のエージェントレジストリを提供し始めると予想される。MCPやA2Aといったプロトコルがデファクトスタンダード化すれば、ベンダーロックインを回避した「オープンなツールディスカバリ層」が登場する可能性が高い。また、エンタープライズ領域ではツールの信頼スコアやガバナンスポリシーを組み込んだ「セキュアレジストリ」への進化が次の焦点になるだろう。KusaBaseとしては、この分野の標準化動向と医療・金融などの高規制業界への応用可能性を継続的にウォッチしていきたい。
